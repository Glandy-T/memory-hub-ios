# Product

## Register

product

## Platform

adaptive

## Users

Memory Hub 首先服务于产品拥有者本人，尤其是在注意力容易被打断、临时想到事情、需要快速回看生活信息的移动场景。Android 是第一真实使用与反馈端；同一 Flutter 工程保留 iOS 目标，后续在 Mac 上完成签名与真机验收。

## Product Purpose

把日程、文档记录、冰箱、采购和物品位置集中成一个安静的外部记忆。核心操作必须低摩擦、可撤销、可恢复；来自其他 Codex 任务的信息必须先进入待收录，由用户确认后才成为正式数据。

## Positioning

Memory Hub 不是生产力评分器，而是一个尊重注意力波动、允许稍后处理和事后修正的私人记忆层。

## Brand Personality

安静、清晰、可信。使用普通中文，不催促、不制造连续签到压力，也不把系统拟人化成聊天助手。

## Anti-references

- 不做聊天机器人、KPI 仪表盘或通用 SaaS 卡片网格。
- 不使用厚重磨砂、霓虹渐变和无意义装饰动效。
- 不为 Android 与 iOS 分裂出两套产品语义；仅对系统导航、弹窗、返回与权限交互进行平台适配。
- 不让外部写入绕过待收录，也不把删除实现成不可恢复的即时销毁。

## Design Principles

1. 今日事项是首页唯一主焦点，其余信息退出首屏。
2. 一次只要求完成当前动作所需的最少字段。
3. 完成、无视、删除和导入都要可理解、可追踪或可撤销。
4. Android 先提供真实反馈，Dart 领域模型、组件和测试同时作为未来 iOS 模板。
5. 遵循平台熟悉的返回、字体缩放、权限和触控语义，不牺牲 Memory Hub 的统一视觉身份。

## Accessibility & Inclusion

支持系统字体缩放、至少 48dp 的 Android 触控目标与至少 44pt 的 iOS 触控目标、减少动态效果、屏幕阅读器标签和足够文字对比度。状态不能只靠颜色表达，纵向手势必须提供可发现的无障碍替代操作。
